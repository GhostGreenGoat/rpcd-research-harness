# Anthropic zeta 案例：他们做了什么，以及 RPCD 可以学什么

日期：2026-08-22。

证据边界：本文主要依据本目录保存的 116 页 Anthropic 原始 PDF。它是两次关键
sub-agent 运行的带注释记录，不是整个项目的完整日志；代理的私有思考文本没有导出。
白色面板是可见运行记录，黄色框是事后编辑注释。本文不独立审核最终论文的全部分析数论
证明，因此把运行中出现的结论称为“候选”；PDF 对后来论文结果的说明称为“编辑注记”。

## 一句话结论

他们没有证明黎曼猜想。真正发生的是：一个代理精确否定了自己受命研究的
“负指标上界”路线，却从同一对象的正指标得到一个 1/2 候选；经多轮敌对审稿和独立
重证后，第二个代理研究前一证明丢掉的结构，借助数值反例搜索发现一个全局 rank-trace
矩阵不等式，把候选推进到 2/3。编辑注记称，最终论文再通过核优化得到约 0.6725。

## 第一阶段：失败路线如何变成 1/2 候选

### 1. 先继承，而不是从零开始

E2 收到一份约 6,135 字符的详细任务书，先读三个早期运行的报告和代码。任务书给定了
对象、文献线索、建议实验、主要风险和交付格式；此前 R4 已观察到一个“密度”在局部为负，
并把相关空间称为 Krein 空间。

这一步的关键不是多代理本身，而是文件化继承：早期代理把报告、笔记、代码、零点表留在
磁盘，后继代理直接读原始工件，没有依赖 orchestrator 口头转述。

### 2. 先纠正对象，再计算

经过约 32 分钟无可见输出的思考，E2 写出一个全局 signature 结论草稿，并纠正任务书的
计数语义：Weil 形式的负指标数的是临界线外“不同零点”，不是带重数计数。随后它指出，
R4 的 33–153 个负特征值来自 warped-sinc 算子，不是 Weil 形式在允许测试函数空间上的
真实压缩。

因此，在已知零点都位于临界线的可计算高度内，正确压缩的负指标必为 0。代理在任何自有
数值实验之前就写下结论：“There is nothing to fit.” 这是本案例最重要的研究纪律之一：
先证明正在测量的是不是目标对象，避免对错误代理量做规模拟合。

### 3. 建立两套独立数值表示

E2 构造同一个 Gram 矩阵的两种实现：

- prime side：由显式公式和有限素数数据计算；
- zero side：由已知 zeta 零点计算，只用于验证。

两边在条目上约符合到 `1e-6`，但第一次正交化后出现了 33 个假负特征值。代理改看原始
Gram 矩阵的特征值，发现质量矩阵条件数高达约 `7.6e9`，负值只是病态正交化放大误差。
这后来也预示了书面证明中会被审稿代理指出的 mass-matrix 归一化缺口。

### 4. 在失败实验里埋入新的诊断量

`exp1.py` 原本用来扫描负指标，却额外记录

\[
\frac{(\operatorname{tr}R)^2}{d\operatorname{tr}(R^2)},
\]

即由两个迹通过 Cauchy–Schwarz 能认证的正特征方向比例。整个负指标表最终全为 0，
但这个“旁路列”成为后续证明的 prime-side 核心。

同时，代理植入假想的临界线外零点，研究它们何时在有限带宽中可见。实验和分析共同显示：
孤立零点有可见性界，但未知相邻零点会相互干涉，簇只产生一个负方向，重数根本不可见。
于是原上界路线不是暂时数值不佳，而是存在明确结构障碍。

### 5. 把同一个对象“反过来数”

关键转折是“the dual use of inertia”：不再用负指标上界临界线外零点，而用正指标下界
临界线上的零点。一个临界线上不同零点最多贡献一个正方向；一个临界线外对也最多贡献
一个正方向，但 Riemann–von Mangoldt 计数把这对算作两个零点。于是超过总数一半的正方向
必须由临界线上的零点解释。

结合 prime side 可计算的 `tr R` 与 `tr(R^2)`，E2 得到 1/2 候选。它随后做了三类检查：

- 更高高度的纯 prime-side 数值验证，测试渐近常数；
- 0%、25%、100% 在临界线上的合成零点世界，检查是否“证明过头”；
- 单独的 referee 版本证明和自我 red-team，首要担忧明确写成“too short to be new”。

### 6. orchestrator 不接受自证

E2 返回时使用的是 `PARTIAL` 和 `claimed theorem`，并主动请求审稿。orchestrator 对人类明确说
“我的先验判断是它错了”，随后把论证拆成三个关节，交给三个互盲代理分别攻击：
窗口外泄漏、prime-side 常数、线性代数计数和 proves-too-much 测试。

审稿发现了真实缺口：tapered window 下质量矩阵并不接近标量恒等阵。独立重证改在原系数
坐标中直接使用实对称 Gram 矩阵，以合同不变性避开病态正交化，常数不受损。另一个审稿
分支把 prime-side 渐近与已发表的无条件 pair-correlation 输入对上。这里的数值吻合没有
替代证明；它只帮助定位和修复证明的薄弱关节。

## 第二阶段：1/2 如何变成 2/3

### 1. 人类给目标，orchestrator 给结构化 brief

人类输入只有“Push it to ⅔”。orchestrator 随即写出约 12,215 字符的任务书，要求研究前一
证明丢掉的 pair-block 与负谱结构，列出候选杠杆、可能的高阶矩路线、已知风险和必须先读的
审稿文件。任务书甚至接近正确的整数算术，但在错误的计数对象上尝试后放弃了相关不等式。

因此，不能把发现简单归因于人类一句鼓励，也不能说代理完全没有继承启发。更准确的分工是：
人类设定高目标并让系统持续运行；orchestrator 组织问题、生成任务书并保持怀疑；sub-agent
在局部数学空间中搜索、计算和证明。

### 2. 先把局部块归一化为“一个单位”

E2-pairs 选择归一化，使一个简单临界线零点恰贡献特征值 1。它用 Poisson 恒等式验证
off-line pair block 的两个非零特征值，并发现不同零点块之间的交叉项可正可负。由此排除
逐块对角占优：任何正确不等式都必须是全局的。

### 3. 用优化器寻找不等式，而不是把优化结果当证明

代理建立纯线性代数模型，用 BFGS 和多起点搜索最小 Frobenius 范数。在 13 组小维配置中，
最小值都精确落在

\[
\|M\|_F^2 = n_{\mathrm{on}}+4n_{\mathrm{pair}},
\]

且极小点谱为 1 和 2 的整数。随后它主动放宽假设：自由质量、自由相位、若干二次推广全部
找到反例。反例说明正确量必须对质量线性，而不是逐块二次求和。

这段过程体现了“cheap falsification”的正确用法：优化负责找结构、杀错误推广和暴露等号
情形；真正的结论随后另行证明。

### 4. 抽象化后出现五行证明

第二次长时间无可见输出后，代理把 zeta 结构压缩成一个纯矩阵命题：

- `M_on` 为 PSD，秩不超过 `r`，迹为 `t_on`；
- `M_p` 为 Hermitian，正特征值个数不超过 `b`，迹为 `t'`。

它提出并用 von Neumann 迹不等式与 Cauchy–Schwarz 证明

\[
\|M_{\mathrm{on}}+M_p\|_F^2
\ge c t_{\mathrm{on}}-\frac{c^2r}{4}+2ct'-c^2b.
\]

随机 400 例没有找到反例，但“证明”来自随后写出的五行代数，不来自这 400 例。

### 5. 故障恢复没有丢失发现

代理在写完抽象定理后遇到 API server error，应用部分还没完成。因为报告和脚本持续写入
磁盘，orchestrator 能在七分半钟内读取存活文件、逐行检查五行证明、独立完成代入得到 2/3，
再恢复同一个代理补齐尾项、边界和数值检查。若只有聊天摘要而没有文件，这个关键发现很可能
会在故障中丢失。

### 6. 最终运行仍保持证据边界

恢复后，代理在真实零点和合成敌对配置上测试新 certificate；在 `T≈1000` 的真实零点上，
新量约为 `0.61N`，旧 1/2 路线约为 `0.38N`，所有合成配置都没有过度认证。然后它把矩阵
不等式与已经审过的 prime-side 迹渐近结合，得到 2/3 distinct-on-line 候选，并明确说明该
局部路线不能同样推出 2/3 simple-on-line。

同时又启动两个互盲审稿代理：一个攻击应用和截断，另一个先独立重证抽象引理，再做大规模
反例搜索。PDF 的编辑注记称，后来论文把该引理称为 rank-trace inequality，并经核优化得到
约 0.6725；这个后续说明不等同于本摘要对最终论文的独立验证。

## 为什么这套流程有效

1. **宽搜和深挖分离。** 更大项目先并行产生许多方向；出现信号后，连续两次约 3.5 小时
   的深挖围绕同一小组工件推进。
2. **失败必须产出结构信息。** “负指标路线为空”不是废稿，而是给出了错误对象诊断、
   可见性障碍和最终正指标对偶的入口。
3. **始终维护双重表示。** prime side 与 zero side 独立实现同一矩阵，能发现代码错误、
   归一化错误和隐藏假设。
4. **先反例搜索，后证明。** 随机/优化实验用于筛掉错误不等式、识别等号结构；一般命题
   仍需完整证明。
5. **审稿按“关节”拆分。** localization、analytic constant、linear algebra、proves-too-much
   由不同代理负责，比让一个代理泛泛读全文更容易发现实质缺口。
6. **文件系统是研究记忆。** 报告、脚本、表格和 proof draft 比对话摘要更高保真，也允许
   独立重证和故障恢复。
7. **orchestrator 保持认识论刹车。** 结果再惊人也先叫 candidate，并公开列出最可能失败处。

## 不应照搬的部分

- 两个关键代理全程没有联网，引用多凭记忆；优先权和精确引理来源必须另设 librarian 审计。
- PDF 不含私有思考，因此无法从日志确认每个创意的精确归属时刻；只能确认可见工件中的首次
  出现。
- 运行中存在病态正交化、阈值选择、线程争用、错误 `pkill`、后台进程和 API 中断；高吞吐
  本身不是可靠性。
- “没有搜到反例”不构成证明；数值渐近吻合也不能替代尾项和量词。
- 很长的 orchestrator brief 已经包含大量数学启发，所以“只靠一句 keep going 自主解决”是
  失真的叙述。

## 对 Iteration 6 前沿的具体用法

当前 RPCD 最新综合已经吸收了这类经验的一部分：C046 把 inverse Bellman potential 以精确
反例关闭；C048 保留了条件回归的 Pythagorean 增量；C049 表明 W4 在 matching、三点 path、
等权 star 上成立，而一般 W4 仍卡在重叠 degree-two、sign-frustrated cycle 和不等权 star。

下一轮最值得仿照的不是机械套用 zeta 的 rank-trace 公式，而是复制它的“发现程序”：

1. **给 W4 建立局部块词典。** 把三个最小未覆盖 support graph 分别归一化，精确写出
   anisotropic surplus、outer Schur defect、交叉项和等号条件。matching/path/star 是正控制，
   cycle/unequal-star 是攻击对象。
2. **搜索全局、线性收费的不等式。** 目前已知每行 scalar summation 不够，就仿照 E2-pairs
   同时放开局部质量、符号和相位，数值最小化完整 W4 residual；系统杀掉所有逐行或二次
   变体，观察极小点是否出现可解释的谱/秩量子化。任何发现先标 E1。
3. **从极小点抽象纯矩阵命题。** 候选应保留 L3 的方向性 surplus 和跨行耦合；目标是类似
   von Neumann/Ky Fan/Pythagorean 的整体控制，而不是把每个 Schur row 单独上界。证明草稿
   才能到 E3。
4. **让 C048 走“双表示”。** 一边保留 cycle-conditioned arc-incidence/Hardy-Copson 精确式，
   另一边按 Fourier mode 或信息增量分解；逐 mode 核对总能量和交叉项。若 scalar Hardy
   损失 `O(n)`，就把损失留在整体 Pythagorean 和中，而不是逐弧绝对值求和。
5. **设置 proves-too-much controls。** 每个候选同时测试 C046 的精确反例、rank-four 低谱
   exterior barrier、equicorrelation、matching、path、star、frustrated cycle，以及接近奇异的
   有理 SPD 矩阵。若候选会推出已知为假的非交换 AGM 或 inverse potential，应立即关闭。
6. **把数值病态列为一等风险。** 对近奇异 `A` 避免无证书的 `A^{-1/2}` 正交化；优先使用
   合同不变的原坐标矩阵、精确有理算术或区间界，并报告条件数、阈值和谱裕量。
7. **继续现有晋级门。** E3 证明稿之后必须由不同运行做 hostile audit，再由另一运行从
   statement 独立重证；优先权和形式化仍单独进行。案例阅读本身不提升 C048/C049 的状态。

建议把下一轮集中为四个边界清楚的任务包：`W4-minimal-blocks`、
`W4-global-aggregate-search`、`cycle-mode-Pythagorean`、`hostile-proves-too-much`。前三者产生
候选，第四个只负责破坏；它们共享精确的 inheritance packet，但不共享结论。

## 对现有 RPCD harness 的评价

仓库的 `docs/METHOD.md` 已经抓住了 Anthropic 案例的主干：idea fan-out、cheap
falsification、selected deep proof、finite verifier、hostile audit、independent reconstruction、
priority audit。现在最应加强的不是再增加一层流程，而是把“失败后的对偶化/补量搜索”和
“全局耦合不等式发现”明确写进下一轮任务设计。Iteration 6 的 L3 anisotropic surplus 已经是一个
正面例子：成功来自保留被早期 Jensen/Bessel scalarization 丢掉的方向信息，这与 zeta 案例从
Cauchy–Schwarz 标量计数转向 rank-trace 全局结构的经验高度一致。
